# 業務フロー帳

業務の手順を、担当ごとのレーンに分けたフロー図（スイムレーン図）で記録するツールです。
`app` フォルダ（HTML ファイルと、見た目・動きを入れた `css`・`js` フォルダ、部品を入れた `lib` フォルダ）をそのまま置けば動き、インストールは要りません。インターネットにつながっていなくても動きます。HTML ファイルだけを取り出すと動かないので、フォルダごと置いてください。

外部のサーバーから読み込むのは、画面の文字のフォント（Google Fonts）だけです。読み込みの際、お使いの端末の IP アドレスやブラウザの情報などが Google に送られます。フローの中身が送られることはありません。つながっていないときは、端末にあるフォントで表示します。

YAML の読み取り部品（[js-yaml](https://github.com/nodeca/js-yaml) 4.1.1、MIT ライセンス）は、`app/lib` に同梱しています。

## 使い方

1. `app/業務フロー帳.html` をブラウザで開きます。
2. 「作業フォルダを選ぶ」で、フローを保存するフォルダを選びます。
3. 左の「ひな形から作成」か「＋ 新規」でフローを作ります。
4. 右の編集エリアで担当（レーン）とステップを登録すると、図が自動で描かれます。図の上でも直接編集できます。

## 保存の仕組み

フローの中身はブラウザ内に保存しません（端末やブラウザのデータから業務フローが漏れないようにするため）。

- **Chrome・Edge**：選んだ作業フォルダに、1 フローずつ YAML ファイル（`.yaml`）として自動で保存します。共有フォルダや Git で管理しているフォルダも選べます。
  - 次に開いたときは「前回のフォルダを開く」で再開できます。ブラウザが覚えているのはフォルダの場所だけで、中身は覚えていません。
  - 別の作業フォルダに切り替えるときは、右上のフォルダ名のボタンを押します。
  - フロー名を変えると、ファイル名も合わせて変わります。
  - ほかのアプリ（エディタ・Git など）でファイルを変えると、画面に戻ったときに反映します。編集中のフローが変わっていた場合は、どちらの内容を残すか選べます。
  - 版の履歴は、作業フォルダの `.flowbook-history` フォルダに 1 フローにつき 1 ファイルで保存します（最大 20 版で、超えると古い版から消えます）。Git で管理する場合は `.gitignore` に入れても構いません。
- **それ以外のブラウザ（Firefox・Safari など）**：開いている間だけ保持します。残したいフローは「エクスポート」（または `Ctrl+S`）で YAML ファイルに保存し、次回は「インポート」で開いてください。保存していない変更があるまま閉じようとすると確認します。

## 主な機能

- **図の上で編集**：ステップを選んで「＋」で追加し、ドラッグで別のステップにつなぎます。ダブルクリックで文言を編集します。ステップをドラッグすると列・段・担当を変えられます（`Shift`+矢印キーでも動かせます）。動かした位置は YAML の `col`・`row` に残り、「位置を自動に戻す」で戻せます。`Ctrl+Z` で元に戻せます。
- **矢印の付け替え**：矢印をクリックで選び、両端の丸をドラッグすると、つなぎ元・つなぎ先や出入りする辺を変えられます。`Delete` で削除します。
- **ステップの種類**：開始・作業・判断・サブプロセス・帳票・データ・データストア・終了があります。サブプロセス・データ・データストアは BPMN 2.0 の Sub-Process・Data Object・Data Store にならっています。
  - **サブプロセス**：別に定義した業務フローを、1 つのステップとして指すときに使います。
  - **データ**：Excel ファイルなど、単体で置くデータ。**データストア**：データベースなど、データを蓄積する場所。
- **関連（点線）**：ステップと、そこで作る・使う帳票などを点線で結びます。**帳票・データ・データストアとの線は、必ず関連になります**（流れの途中には置きません）。「＋」から `Shift` を押しながらドラッグすると関連で結びます。YAML では `related` に相手のステップ ID を書きます。
- **色**：ステップごとに箱の色を選べます（任意。開始・終了は選べません）。
- **補足・課題・使用システム・ツール・手段**：ステップごとに書けます。図ではステップにマウスを乗せると表示します。図の上の「課題を表示」で課題を吹き出しで、「ツール・手段を表示」でツールを箱の中に常に表示します。
- **メモ**：図の下の「メモ」欄に、フロー全体についてのメモを書けます。YAML の `memo` に保存され、手順書（.md）にも入ります。
- **表示**：`Ctrl`+ホイールか「−」「＋」で拡大縮小、「図だけ表示」で図を画面いっぱいに広げます。「凡例」で記号の凡例を開け閉めします。
- **チェック**：行き止まりや、開始からたどり着けないステップを知らせます。
- **インポート・エクスポート**（右上）：YAML / JSON ファイルを読み込めます。YAML・Mermaid 記法のコピーと、YAML（.yaml）・手順書（.md）の保存ができます。
- **画像として出力**（「エクスポート」の中）：図を PNG 画像にして、PowerPoint などに貼れます。
  - 貼る場所は「スライド全体（16:9）」「本文エリア（16:7）」「分割しない（図全体を 1 枚）」から選べます。貼るとスライドや本文エリアの幅の大きさになります。
  - 長いフローは、貼ったときのステップの文字の大きさ（約 8pt・10pt・12pt）に合わせて、列の切れ目で複数枚に分けます。枚をまたぐ矢印は、結合子（丸に A・B…）でつなぎます。
  - フロー名と枚数・凡例・課題の吹き出し・ツール・手段を入れるかどうかを選べます。
  - 「コピー」で 1 枚ずつクリップボードに入れて `Ctrl+V` で貼れます。「保存」では PNG ファイルに書き出します。

## フローの書き方（YAML）

```yaml
name: 経費精算フロー
lanes:
  - id: applicant
    name: 申請者
  - id: manager
    name: 上長
steps:
  - id: s1
    type: start        # start / task / decision / subProcess / document / dataObject / dataStore / end（以前の data は dataStore、system は subProcess として読みます）
    lane: applicant
    col: 1             # 図で左から何列目に置くか（任意）。省くと自動
    row: 1             # レーンの中で上から何段目に置くか（任意）。省くと自動
    color: blue        # 箱の色（任意。開始・終了は塗りません）：red / orange / yellow / green / blue / purple / gray（赤・青などの日本語でも可）
    label: 精算申請を作成
    note: 領収書の画像を添付する          # 補足（任意）
    issue: 添付漏れによる差戻しが多い     # 課題（任意）
    tool: 経費精算システム・メール       # 使用システム・ツール・手段（任意）
    next: s2
    related: d1        # 関連（任意）：点線で結ぶ帳票など。複数なら [d1, d2]
  - id: d1
    type: document
    lane: applicant
    label: 精算申請書
  - id: s2
    type: decision
    lane: manager
    label: 内容は妥当か
    next:
      - to: s3
        when: 承認
      - to: s1
        when: 差戻し
        exit: right    # 出る辺（任意）：top / bottom / left / right。省くと自動
        entry: right   # 入る辺（任意）
  - id: s3
    type: end
    lane: applicant
    label: 完了
memo: |-               # フロー全体のメモ（任意）。複数行は「|-」の下に字下げして書く
  承認の上限額を経理部と決める
```

## 以前のバージョンの YAML を移行する

以前のバージョン（v1.x・v2.0.x・v2.1.x）の YAML も、そのまま開けます。ただし、次のところは読み込むときに機械的に置き換えます。

- v2.0.0 から、帳票・データは流れの途中に置かず、ほかのステップとは関連（点線・`related`）で結ぶ書き方になりました。帳票・データを流れの途中に置いていたフローは、開くとその前後が点線になり、流れが途切れます。
- v2.1.0 から、以前の「データ」（`data`・円柱）はデータストア（`dataStore`）として読みます。
- v2.1.0 から、入力情報・出力情報・関連ファイル・帳票（`input`・`output`・`files`）は補足の末尾に移します。伝達手段（`channel`）は、使用システム・ツール・手段（`tool`）につなぎます。
- v2.2.0 から、以前の「システム」（`system`）はサブプロセス（`subProcess`）として読みます。システムで行う作業を `system` で書いていたステップは、作業（`task`）に直してください。

流れのつなぎ直し、データとデータストアの選び分け、システムを作業とサブプロセスに分ける作業、入出力の帳票・ファイルを関連で結ぶ作業は、LLM（ChatGPT・Claude など）に任せられます。[migration/v2.2へのYAML移行プロンプト.md](migration/v2.2へのYAML移行プロンプト.md) のプロンプトに YAML を貼り付けて渡してください。

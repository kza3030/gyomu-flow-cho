# 業務フロー帳

業務の手順を、担当ごとのレーンに分けたフロー図（スイムレーン図）で記録するツールです。
`app` フォルダ（HTML ファイルと、見た目・動きを入れた `css`・`js` フォルダ、部品を入れた `lib` フォルダ）をそのまま置けば動き、インストールは要りません。インターネットにつながっていなくても動きます。HTML ファイルだけを取り出すと動かないので、フォルダごと置いてください。

外部のサーバーから読み込むのは、画面の文字のフォント（Google Fonts）だけです。読み込みの際、お使いの端末の IP アドレスやブラウザの情報などが Google に送られます。フローの中身が送られることはありません。つながっていないときは、端末にあるフォントで表示します。

YAML の読み取り部品（[js-yaml](https://github.com/nodeca/js-yaml) 4.1.1、MIT ライセンス）は、`app/lib` に同梱しています。

## 使い方

1. `app/業務フロー帳.html` をブラウザで開きます。
2. 「作業フォルダを選ぶ」で、フローを保存するフォルダを選びます。
3. 左の「ひな形から作成」か「＋ 新規」でフローを作ります。
4. 右の編集エリアで担当（レーン）とステップを登録すると、図が自動で描かれます。図の上でも直接編集できます。

## 保存の仕組み

フローの中身はブラウザ内に保存しません（端末やブラウザのデータから業務フローが漏れないようにするため）。

- **Chrome・Edge**：選んだ作業フォルダに、1 フローずつ YAML ファイル（`.yaml`）として自動で保存します。共有フォルダや Git で管理しているフォルダも選べます。
  - 次に開いたときは「前回のフォルダを開く」で再開できます。ブラウザが覚えているのはフォルダの場所だけで、中身は覚えていません。
  - フロー名を変えると、ファイル名も合わせて変わります。
  - ほかのアプリ（エディタ・Git など）でファイルを変えると、画面に戻ったときに反映します。編集中のフローが変わっていた場合は、どちらの内容を残すか選べます。
  - 版の履歴は、作業フォルダの `.flowbook-history` フォルダに 1 フローにつき 1 ファイルで保存します（最大 20 版で、超えると古い版から消えます）。Git で管理する場合は `.gitignore` に入れても構いません。
- **それ以外のブラウザ（Firefox・Safari など）**：開いている間だけ保持します。残したいフローは「エクスポート」（または `Ctrl+S`）で YAML ファイルに保存し、次回は「インポート」で開いてください。保存していない変更があるまま閉じようとすると確認します。
- 以前のバージョンでブラウザ内に保存していたフローは、初めて開いたときに作業フォルダへ移す（またはファイルに保存してから削除する）よう案内します。

## 主な機能

- **図の上で編集**：ステップを選んで「＋」で追加し、ドラッグで別のステップにつなぎます。ダブルクリックで文言を編集し、ステップを左右にドラッグすると列が、上下にドラッグすると段が、別のレーンへドラッグすると担当が変わります（`Shift`+矢印キーでも動かせます）。動かした列・段は YAML の `col`・`row` に残り、フォームの「位置を自動に戻す」で自動の配置に戻せます。`Ctrl+Z` で元に戻せます。
- **レーンの中の段**：1 つのステップから同じレーンへ 2 つ以上に分かれた先は、右へずらさず同じ列に縦に並べます（レーンに段ができ、その分レーンが高くなります）。段のあとに同じレーンで続くステップは同じ段を引き継ぎ、合流するステップは一番上の段に置きます。
  - ステップをほかのステップの上や、段と段の境目（レーンの一番上・一番下を含む）へドラッグすると、そこにあったステップとその下（同じ列）が 1 段ずつ下がります。ほかの列のステップは動きません。一番下の境目へ置くと新しい段になり、中身のない段は詰めて表示します。
- **差し戻しの矢印**：戻り先のステップの下へ入れるのが基本ですが、戻り先の左の辺が空いていて、左から入るほうが近い場合は左へ入れます。
- **矢印の付け替え**：矢印をクリックで選び、両端の丸をドラッグすると、つなぎ元・つなぎ先を変えられます。ステップの辺の近くで離すとその辺（上下左右）から出入りし、真ん中で離すと自動の位置に戻ります。`Delete` で矢印を削除します。
- **つながりの強調**：ステップや矢印にマウスを乗せる（キーボードで選ぶ）と、出入りする矢印と条件が強調されます。
- **補足と課題**：ステップごとに補足と課題（問題点・改善したい点）を書けます。図の右上に、補足はメモのアイコン、課題は赤い「!」のアイコンで表示し、ステップにマウスを乗せると補足→課題の順にツールチップで表示します。
- **課題を表示**：図の上の「課題を表示」を押すと、課題をステップのそばの吹き出しで常に表示し、ステップと短い線でつなぎます（もう一度押すと元に戻ります。オン・オフはこの端末で覚えておきます）。
  - 吹き出しは、矢印が出入りしない側（上を優先）に置きます。幅は、近くを通る線や隣の吹き出しとぶつからない範囲で広げ（最大 300px）、高さは文の長さに合わせます（最大 4 行）。
  - 4 行に収まらない課題は「…」で省き、ステップか吹き出しにマウスを乗せる（または選ぶ）と全文を表示します。
  - 吹き出しをクリックするとそのステップを選び、ダブルクリックすると編集エリアの課題の欄で書き直せます。
  - 表示中は、ステップ右上の課題のアイコンは出しません（しるしが二重にならないように）。
- **拡大縮小**：`Ctrl`+ホイール、または「−」「＋」で 10% ずつ拡大縮小します。
- **メモ**：図の下の「メモ」欄に、フロー全体についてのメモ（検討の経緯・決まっていないこと・ToDo など）を自由に書けます。見出しを押すと開け閉めでき、閉じているときは 1 行目だけを表示します。欄の上の境目をドラッグすると高さを変えられます（開け閉めと高さはこの端末で覚えておきます）。メモは YAML の `memo` に保存され、手順書（.md）にも入ります。フローの「説明」とは別の項目です。
- **図だけ表示**：フロー一覧と編集エリア・メモを隠して、図を画面いっぱいに広げます。
- **チェック**：行き止まりや、開始からたどり着けないステップを知らせます。
- **インポート**（右上）：YAML / JSON ファイルを読み込めます（複数まとめて選べます）。
- **エクスポート**（右上）：YAML・Mermaid 記法のコピーと、YAML（.yaml）・手順書（.md）・データ（.json）の保存ができます。Chrome・Edge では保存場所とファイル名を選べます（それ以外のブラウザでは、ブラウザのダウンロード先に保存されます）。
- **画像として出力**（「エクスポート」の中）：図を PNG 画像にして、PowerPoint などに貼れます。
  - 貼る場所は「スライド全体（16:9）」「本文エリア（16:7、タイトルの下に貼る場合）」「分割しない（図全体を 1 枚）」から選べます。画像には解像度を書き込んであり、貼るとスライドや本文エリアの幅の大きさになります。
  - 1 枚に入れる量は、貼ったときのステップの文字の大きさ（約 8pt・10pt・12pt）で決めます。収まらない長いフローは、列の切れ目で複数枚に分けます。ステップ・条件ラベル・課題の吹き出しは切れ目で割りません。
  - 分け方は、16:9 では各枚の幅をそろえ、横長の 16:7 では右に余白が出すぎないよう、各枚に列をぎりぎりまで詰めます（余りは最後の枚に入ります）。
  - どの枚にも左端にレーン名の列を付け、全枚を同じ縮尺・同じ大きさにします。枚をまたぐ矢印は、切れ目の両側に同じ文字の結合子（丸に A・B…）と「2枚目へ」「1枚目から」を付けてつなぎます。
  - レーンが多く 1 枚の高さに収まらないときは、文字を小さくして収めます（出力画面に何 pt になるかを表示します）。
  - フロー名と枚数（例：経費精算フロー（1/3））、凡例、課題の吹き出し、ステップ ID を入れるかどうかを選べます。凡例は図に出てくる記号・線だけを並べ（複数枚では結合子も）、見出しの行の右に置きます（フロー名と並ばないときは 2 行目）。補足・課題のしるしやチェックの警告は入れません。色はいつもライトテーマで、背景は白です。
  - 「コピー」で 1 枚ずつクリップボードに入れ、PowerPoint で `Ctrl+V` で貼れます。「保存」では PNG ファイルに書き出します（複数枚は、選んだフォルダに「フロー名_1.png」「フロー名_2.png」…として保存します）。保存できたら出力画面を閉じます。
  - 画像の文字は、端末にあるフォント（Windows では游ゴシック UI）で描きます。

## フローの書き方（YAML）

```yaml
name: 経費精算フロー
lanes:
  - id: applicant
    name: 申請者
  - id: manager
    name: 上長
steps:
  - id: s1
    type: start        # start / task / decision / system / document / data / end
    lane: applicant
    col: 1             # 図で左から何列目に置くか（任意）。省くと自動
    row: 1             # レーンの中で上から何段目に置くか（任意）。省くと自動
    label: 精算申請を作成
    note: 領収書の画像を添付する          # 補足（任意）
    issue: 添付漏れによる差戻しが多い     # 課題（任意）
    next: s2
  - id: s2
    type: decision
    lane: manager
    label: 内容は妥当か
    next:
      - to: s3
        when: 承認
      - to: s1
        when: 差戻し
        exit: right    # 出る辺（任意）：top / bottom / left / right。省くと自動
        entry: right   # 入る辺（任意）
  - id: s3
    type: end
    lane: applicant
    label: 完了
memo: |-               # フロー全体のメモ（任意）。複数行は「|-」の下に字下げして書く
  承認の上限額を経理部と決める
```

## フォルダ構成

| パス | 内容 |
| --- | --- |
| `app/業務フロー帳.html` | アプリ本体（画面の骨組み。これをブラウザで開く） |
| `app/css/style.css` | 画面の見た目 |
| `app/js/app.js` | アプリの動き |
| `app/lib/` | 外部の部品（js-yaml） |
| `samples/` | 読み込んで試せるサンプルの YAML |

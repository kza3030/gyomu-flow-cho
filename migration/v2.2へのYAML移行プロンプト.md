# v2.2 への YAML 移行プロンプト

業務フロー帳の以前のバージョン（v1.x・v2.0.x・v2.1.x）で作ったフローの YAML を v2.2.0 の書き方に直すために、LLM（ChatGPT・Claude など）へ渡すプロンプトです。

## 使い方

1. 下の「プロンプト」の枠の中を、すべてコピーします。
2. LLM に貼り付け、最後の `（ここに YAML を貼り付ける）` を、移行したいフローの YAML ファイルの中身に置き換えて送ります。
3. 返ってきた YAML を、元のファイルと同じ名前で保存し直すか、業務フロー帳の「インポート」で読み込みます。
4. 業務フロー帳で開き、図と「チェック」タブを確かめます。返答の最後にある「判断した点」も読み、意図と違うところは直してください。

- 1 回に渡すのは 1 フロー（1 ファイル）にしてください。
- 移行前のファイルは、念のため別の場所に残しておいてください。

### このプロンプトを使う理由

v2.2 の業務フロー帳は、以前の YAML もそのまま開けます。ただし、読み込むときに機械的に置き換えるだけです。

| 以前の書き方 | 業務フロー帳が読み込むときにすること | このプロンプトで LLM にさせること |
| --- | --- | --- |
| 帳票・データを流れ（`next`）の途中に置く | 前後の矢印を関連（点線）に置き換える。流れはそこで途切れる | 流れをつなぎ直し、帳票・データを関連でぶら下げる |
| `type: data`（円柱） | すべてデータストア（`dataStore`）にする | ラベルを見て、データストアか、単体のデータ（`dataObject`）かを選び分ける |
| `input`・`output`・`files`（入力情報・出力情報・関連ファイル・帳票） | 「入力情報：…」の行にして補足（`note`）の末尾に足す | 帳票・ファイルの名前なら帳票・データのステップにして関連で結ぶ。それ以外は補足に足す |
| `channel`（伝達手段） | `tool` の後ろに「 ／ 」でつなぐ | 同じ |
| `type: system`（システム） | すべてサブプロセス（`subProcess`）にする | ラベルを見て、別の業務フローを指すならサブプロセス、システムで行う作業なら作業（`task`）に選び分ける |

## プロンプト

````text
あなたは業務フローの YAML を整える担当です。
「業務フロー帳」というツールの以前の形式（v1.x・v2.0.x・v2.2.x）で書かれたフローの YAML を、v2.1 の形式に書き直してください。

# 以前の形式と v2.2 の違い

1. 帳票（document）・データは、流れ（next）の途中に置かない。
   - 以前は、帳票・データのステップを作業と同じように next でつないでいました。
   - v2.2 では、BPMN 2.0 の「関連」にならい、帳票・データ・データストアとほかのステップは、入力・出力とも必ず関連（related。図では点線）で結びます。
   - 以前、点線の矢印は「差し戻し」を表していましたが、今は関連を表します。差し戻しは普通の流れ（next）のままで、直す必要はありません。
2. 「データ」が 2 つの種類に分かれた（名前は BPMN 2.0 の Data Object・Data Store にならう）。
   - dataObject（データ）：Excel ファイル・CSV・PDF・振込データなど、単体で置くデータ。
   - dataStore（データストア）：データベース・マスタ・システムの台帳など、データを蓄積する場所。
   - 以前の type: data（円柱）は、どちらかにします。
3. 入出力・システムの項目（input・output・files・tool・channel）は、tool（使用システム・ツール・手段）の 1 項目になった。
   - 入力・出力の帳票やファイルは、項目に書くのではなく、帳票・データのステップにして関連で結びます。
4. system（システム）はなくなり、subProcess（サブプロセス）になった。
   - subProcess（サブプロセス）：別に定義した業務フローを、1 つのステップとして指すもの（BPMN 2.0 のサブプロセス）。
   - システムで行う作業は、ほかの作業と同じ task にします（使うシステムは tool に書けます）。

# v2.2 の YAML の書き方

```yaml
name: フロー名
owner: 管理部署            # 任意
description: 説明          # 任意
lanes:
  - id: applicant
    name: 申請者
steps:
  - id: s1
    type: task             # start / task / decision / subProcess / document / dataObject / dataStore / end
    lane: applicant
    col: 1                 # 任意。図で左から何列目か
    row: 1                 # 任意。レーンの中で上から何段目か
    color: blue            # 任意。箱の色（red / orange / yellow / green / blue / purple / gray）。開始・終了には付けない
    label: 申請書を作成
    note: 補足             # 任意
    issue: 課題            # 任意
    tool: Excel・メール    # 任意。使用システム・ツール・手段
    next: s2               # 流れ。1 つなら ID、複数なら並び。条件などは「- to: s2 / when: 承認」の形
    related: d1            # 関連（点線）。1 つなら ID、複数なら [d1, d2]
  - id: d1
    type: document
    lane: applicant
    label: 申請書
memo: |-                   # 任意
  フロー全体のメモ
```

- この形式にない項目（input・output・files・channel など）は書きません。
- related は「関連元」のステップに書き、向きは「関連元 → 相手」です。
  - 出力（ステップで作る帳票・データ）：作業の related に帳票・データの ID を書く（例：s1 の related: d1）。
  - 入力（ステップで使う帳票・データ）：帳票・データの related に作業の ID を書く（例：d1 の related: s5）。
- 帳票・データ・データストア（document・dataObject・dataStore）のステップには next を書きません。どのステップの next にも、これらの ID を書きません。
- related には条件（when）や出入りする辺（exit / entry）は書けません。

# 直し方

次の 1〜5 の順に直してください。

## 1. type: data を dataObject か dataStore にする

- ラベルが、データを蓄積する場所（「顧客DB」「商品マスタ」「会計システムの台帳」など）なら dataStore。
- ラベルが、単体で置くデータ（「振込データ」「売上一覧.xlsx」「CSV ファイル」など）なら dataObject。
- 迷うときは dataStore にし（以前と同じ円柱の見た目になる）、「判断した点」に書いてください。

## 2. 帳票・データを流れからはずす

帳票・データ・データストアのステップ（以下まとめて「帳票・データ」）が next でほかのステップとつながっているところを、すべて次の A か B に直します。

### A. 帳票・データのステップが、実は「手順」の場合

ラベルが「〜を発行」「〜を作成」「〜を提出」「〜を受領・照合」のような動作になっているもの。例：type: document / label: 請求書を発行。

1. そのステップの type を task に変えます。ID・担当・ラベル・next・ほかの項目はそのまま残します。
2. 成果物の帳票・データを、新しいステップとして足します。
   - type：紙の書類・帳票なら document、ファイルなどのデータなら dataObject。
   - label は成果物の名前にします（例：「請求書を発行」なら「請求書」）。
   - lane は元のステップと同じ担当にします。
   - ID は、ほかと重ならない新しいもの（d1, d2, … のように、使われていない番号）にします。
   - col・row は書きません。
3. 元のステップの related に、新しい帳票・データの ID を書きます（出力の関連）。
4. 新しいステップは、元のステップのすぐ後ろに並べます。

### B. 帳票・データのステップが、本当に「成果物」の場合

ラベルが名詞（「申請書」「出荷指示データ」など）で、作業と作業の間に置かれているもの。例：s2（作業）→ d1（帳票）→ s3（作業）。

1. 流れをつなぎ直します。帳票・データの前のステップの next にある帳票・データの ID を、帳票・データの next の先（s3）に置き換えます。
   - 前のステップの next に条件（when）や辺の指定（exit / entry）があれば、置き換えた後もそのまま残します。
   - 帳票・データの next の先が複数あるときは、前のステップの next にすべて足します。
   - 置き換えた結果、前のステップの next に同じ ID が 2 つ並ぶときは、1 つにまとめます。
2. 帳票・データの next を消します。
3. 関連を付けます。
   - 前のステップ（作ったステップ）の related に、帳票・データの ID を足します（出力）。
   - 帳票・データの related に、後ろのステップ（使ったステップ）の ID を足します（入力）。すぐ次の作業が使うだけなど、わざわざ書く意味が薄いときは、出力の関連だけでも構いません。

### A・B に共通の決まり

- 判断（decision）の分岐が帳票・データを指していたら、B の 1 と同じく、その帳票・データの次のステップへ向け直します。分岐の条件（when）は残します。
- 開始（start）や終了（end）の直前・直後に帳票・データがあるときも、同じように流れをつなぎ直し、開始から終了まで流れ（next）だけでたどれるようにします。
- 帳票・データが何ともつながっていない（どこからも next で指されず、自分の next もない）ときは、そのまま残します。
- A と B のどちらか迷うときは、ラベルが動作（動詞で終わる）なら A、名詞なら B にし、どう判断したかを「判断した点」に書いてください。

## 3. input・output・files を、帳票・データのステップと関連にする

ステップに input（入力情報）・output（出力情報）・files（関連ファイル・帳票）があれば、値を 1 つずつ見ます。値は「、」「・」や改行で複数書かれていることがあります。

- 値が帳票・ファイル・データの名前（「申請書」「申請書.xlsx」「管理台帳」「見積書（PDF）」など）なら、帳票・データのステップにして関連で結びます。
  - type：紙の書類・帳票なら document、ファイルやデータなら dataObject、データベース・マスタなら dataStore。
  - label は、その名前をそのまま使います。
  - 同じ名前の帳票・データのステップがすでにあれば、新しく作らずにそれを使います。
  - 新しく作るときは、lane はそのステップと同じ担当にし、ID は使われていない番号（d1, d2, …）にして、そのステップのすぐ後ろに並べます。
  - input の値なら入力の関連（帳票・データの related にそのステップの ID）、output の値なら出力の関連（そのステップの related に帳票・データの ID）にします。files の値は、input・output のどちらにも同じものがなければ出力の関連にします。
- 値が帳票・ファイル・データの名前ではないもの（「承認依頼」「口頭での指示」など）は、補足（note）の末尾に「入力情報：〜」「出力情報：〜」「関連ファイル・帳票：〜」の行として足します（元の note は消さずに、その後ろに改行して足します）。
- 迷うときは補足に足し、「判断した点」に書いてください。
- 終わったら、input・output・files の項目は消します。

## 4. tool と channel をまとめる

- channel（伝達手段）があれば、tool の後ろに「 ／ 」でつないで 1 つにし、channel の項目は消します（tool がなければ channel の値をそのまま tool にします）。
- color は付けません（以前の形式にはありません）。

## 5. type: system を task か subProcess にする

- ラベルが、別に定義した業務フローを指すもの（「出荷フロー」「月次決算の手続き」「〜処理（別紙）」など）なら subProcess。
- ラベルが、システムで行う動作（「受注を登録」「仕訳を登録」など）なら task。
- 迷うときは task にし、「判断した点」に書いてください。

# 変えてはいけないもの

- 上に書いた直し方以外の変更はしないでください。
  - ステップ・担当の ID、ラベル、note・issue・tool、memo、name・owner・description は一字も変えない。
    - 例外：A で足す成果物のステップ、3 で note の末尾に足す行、4 で tool につなぐ channel の値は除く。
  - 帳票・データとつながっていない next（差し戻しを含む）は変えない。
  - ステップと担当の並び順は変えない。新しいステップを足す位置は、上の決まりのとおりにする。
- コメント（# から行末まで）は、残せるものは残してください。
- 書いていない項目を新しく足さないでください（空の note などを書き足さない）。

# 確かめること

書き直した YAML が、次をすべて満たすか確かめてから返してください。

1. type が start・task・decision・subProcess・document・dataObject・dataStore・end のどれかで、data・system は残っていない。
2. input・output・files・channel の項目が残っていない。
3. type が document・dataObject・dataStore のステップに next がない。
4. どのステップの next にも、type が document・dataObject・dataStore のステップの ID がない。
5. related と next に書いた ID が、すべて steps にある。
6. 開始（start）から next だけをたどって、帳票・データ以外のすべてのステップへ行ける（以前の YAML で行けなかったステップは除く）。
7. 判断（decision）の分岐の数と条件（when）が、以前と同じ（向け直した先だけが違う）。
8. 以前の input・output・files の値が、帳票・データのステップと関連、または補足の行として、すべてどこかに残っている。
9. YAML として正しく読める（字下げ・記号のエスケープ）。

# 返し方

次の 3 つを、この順で返してください。

1. 書き直した YAML の全文（```yaml のコードブロック 1 つ。省略しない）
2. 変更点の一覧（「s7：document → task。成果物 d1『振込データ』（dataObject）を追加して related で結んだ」のように、ステップごとに 1 行）
3. 判断した点（A・B の判断、data を dataObject と dataStore のどちらにしたか、system を task と subProcess のどちらにしたか、入出力の値を帳票・データにしたか補足に足したかで迷ったものなど。なければ「なし」）

# 以前の YAML

（ここに YAML を貼り付ける）
````

## 直し方の例

### 帳票を手順として流れに置いていた場合（v1）

経費精算フロー（v1 のひな形）の最後の部分です。帳票「振込データを作成」は動作なので、A の直し方になります。振込用のファイルなので、成果物は dataObject にします。システムで行う「仕訳を登録」（system）は、5 の直し方で task にします。

以前：

```yaml
  - id: s6
    type: system
    lane: erp
    label: 仕訳を登録
    next: s7
  - id: s7
    type: document
    lane: accounting
    label: 振込データを作成
    note: 毎月25日締め・翌月10日払い
    next: s8
  - id: s8
    type: end
    lane: applicant
    label: 指定口座へ入金
```

v2.2：

```yaml
  - id: s6
    type: task
    lane: erp
    label: 仕訳を登録
    next: s7
  - id: s7
    type: task
    lane: accounting
    label: 振込データを作成
    note: 毎月25日締め・翌月10日払い
    next: s8
    related: d1
  - id: d1
    type: dataObject
    lane: accounting
    label: 振込データ
  - id: s8
    type: end
    lane: applicant
    label: 指定口座へ入金
```

### 入出力・システムの項目を書いていた場合（v1.9〜v2.0）

以前：

```yaml
  - id: s2
    type: task
    lane: accounting
    label: 台帳に転記
    input: 申請書.xlsx
    output: 承認依頼
    tool: Excel
    channel: メール
    next: s3
```

v2.2（「申請書.xlsx」はファイルなので入力の関連に、「承認依頼」は帳票・ファイルではないので補足に移す）：

```yaml
  - id: s2
    type: task
    lane: accounting
    label: 台帳に転記
    note: 出力情報：承認依頼
    tool: Excel ／ メール
    next: s3
  - id: d1
    type: dataObject
    lane: accounting
    label: 申請書.xlsx
    related: s2
```
